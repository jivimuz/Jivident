# Audit Fitur & TODO — Jivident

Hasil audit kode per 2026-10-27. Daftar ini dibagi: (1) fitur yang sudah ada, (2) bug/fitur setengah jadi yang ditemukan di kode, (3) fitur umum klinik yang belum ada, (4) technical debt.

## 1. Fitur yang sudah ada

| Modul | Fungsi |
|---|---|
| **Auth & Lisensi** | Login/logout session-based, gate lisensi/serial global (cek remote server), reset password oleh admin |
| **Akses & User** | CRUD user, assign akses per modul (bukan role), manajemen jabatan |
| **Pendaftaran Pasien** | CRUD pasien, cari alamat (provinsi→kelurahan), daftar kunjungan harian, registrasi ke dokter |

## 4. Technical debt / kualitas kode

- [x] **Tidak ada test sungguhan.** Ditambahkan 24 test (`tests/Unit/ProductQtyHelperTest.php`, `tests/Unit/TransactionHelperTest.php`, `tests/Feature/AuthApiMiddlewareTest.php`) yang cover: FEFO stock-out ordering, guard stok tidak cukup/expired, `processReceiveOrder`/`rebuildReceiveOrderMutations`, guard clause & kalkulasi status pembayaran di `TransactionHelper::createTransaction`, dan skenario gate lisensi (tidak ada serial, serial kosong, expired, bypass `TYPE_LOCAL_SERVER=2`, caching remote-check). `tests/Feature/ExampleTest.php` (skeleton bawaan) juga diperbaiki — sebelumnya mengasumsikan `/` mengembalikan 200 untuk guest, padahal app ini selalu redirect ke lisensi/login.
  - **Bug ketemu & langsung diperbaiki saat menulis test ini:** di `AuthApiMiddleware`, variabel `$shouldCheckRemote` dihitung dengan benar (cache 3 jam) tapi baris setelahnya langsung di-override jadi `true` tanpa kondisi — artinya **setiap request** ke seluruh app memanggil HTTP endpoint lisensi eksternal (timeout 8 detik), bukan cuma sekali per 3 jam seperti niatnya. Ini kemungkinan besar biang "aplikasi kadang lambat". Baris override itu sudah dihapus.
  - **Catatan untuk siapa pun yang menambah test ke depannya:** `phpunit.xml` tidak men-override `TYPE_LOCAL_SERVER`, jadi test sebelumnya diam-diam mewarisi nilai dari `.env` lokal developer (kalau di `.env`-mu `TYPE_LOCAL_SERVER=2`, gate lisensi otomatis bypass saat test, beda hasil di komputer lain). Sudah ditambahkan `<env name="TYPE_LOCAL_SERVER" value="0"/>` di `phpunit.xml` supaya deterministik — kalau menambah env var baru yang dibaca lewat `env()` langsung (bukan `config()`), pertimbangkan override juga di `phpunit.xml`.
- [ ] **String obfuscation (octal escape) di `AuthApiMiddleware`** menyulitkan maintenance & review kode ke depannya — pertimbangkan simpan logic lisensi di package/service terpisah yang jelas, kalau tujuannya memang menyembunyikan dari pelanggan yang punya akses source.
- [x] **Vite/Tailwind yang tidak dipakai sudah dibuang** — `vite.config.js`, `resources/css/app.css`, `resources/js/app.js`/`bootstrap.js` dihapus; `package.json` sekarang cuma berisi `concurrently` (dipakai `composer dev`); `composer.json` script `setup`/`dev` dirapikan (tidak lagi `npm install`/`npm run build`/proses vite). Dicek dulu tidak ada satupun Blade yang referensi `@vite`/`resources/js`/`resources/css` sebelum dihapus. `CLAUDE.md` sudah diperbarui.
- [ ] **Validasi input masih manual** di banyak controller (bukan Form Request) — konsisten dengan gaya `ProductQtyHelper`/`TransactionHelper`, tapi membuat validasi gampang terlewat di controller baru.
- [x] **PPN tidak pernah terhitung di HPP produk — sudah diperbaiki.** `ProductQtyHelper::processReceiveOrder()` sebelumnya membaca `$d->ppn_persen` dari baris `t_receiveorderdetails`, padahal kolom itu tidak ada di tabel tersebut (selalu jatuh ke 0 lewat `?? 0`). Sesuai arahan: PPN sekarang jadi **setting global**, bukan per-item/per-faktur — ditambahkan parameter `ppn_persen` (default 11%, bisa diubah dari halaman Setting) lewat migration `2026_02_26_000000_add_ppn_persen_setting.php`, dan `updateProductPrices()` dipanggil dengan nilai dari setting ini. Sudah dites (`test_process_receive_order_applies_global_ppn_setting_to_hpp`) dan migration sudah dijalankan di DB dev.
